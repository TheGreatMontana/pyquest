**Сильные стороны:** XP-значения вынесены в конфиг, защита от повторного начисления реализована (флаги `theory`, `tasks[id]`, сравнение с `quizBest`/`examBest`).

**Слабые стороны:** начисление происходит на клиенте, сервер принимает любое присланное состояние (`PUT /api/state` не валидирует XP). Для дружеского круга приемлемо, для публичной платформы — нет.

## 7. Хранение прогресса

**Клиент:** `localStorage['pyquest_v1']` — единый объект состояния; `pyquest_auth` — токен; `pyquest_code_<mod>_<task>` — черновики кода; `pyquest_last_user` — для защиты от смешения аккаунтов.

**Сервер:** таблица `states(user_id, data TEXT, updated)` — тот же JSON целиком.

**Схема состояния:**
```js
{ xp, streak, lastDay, start, name, finalBest,
  mods: { m01: { theory, quizBest, tasks: {t1:true}, examBest, examPerfect } },
  ach: [...], rm: { <roadmap-item-id>: true } }
```

**Риск при миграции:** ключи модулей (`m01`, `s01`, `a01`) зашиты в состояние. При переименовании модулей прогресс потеряется — **обязательна карта соответствия старых и новых идентификаторов**.

## 9. Слабые стороны

1. **`app.js` — монолит** (~1000 строк): роутер, состояние, авторизация, рендер, геймификация в одном файле. Расширять до платформы в таком виде тяжело.
2. **Контент как исполняемый JS** с побочным эффектом (`COURSE_DATA.m01 = {...}`) — не данные, а код; нельзя редактировать без риска синтаксической ошибки.
3. **Всё грузится сразу**: 26 тегов `<script>`, 219 КБ контента на первой загрузке, даже если пользователь откроет один модуль. При 16 доменах это неприемлемо.
4. **Только русский язык** — жёстко зашит в строки данных и в код рендера.
5. **Архитектура заточена под 3 трека**: `COURSE.tracks` и `COURSE.modules` — плоские массивы без понятий «домен», «карьера», «навык», «курс».
6. **Нет пререквизитов между треками** (кроме одного частного случая `algo.needs = 'm08'`).
7. **Нет переиспользования курсов**: Python существует только внутри DE, для AI/Backend пришлось бы дублировать.
8. **Роадмап — плоский чеклист**, не визуальный граф.
9. **Нет оценки уровня** (assessment) — новичок и опытный идут одним путём.
10. **Один тип урока** (теория → квиз → задачи → экзамен), нет разнообразия блоков (найди баг, предскажи вывод, сопоставь, упорядочь).
11. **Дашборд декоративен**: показывает прогресс, но не даёт диагностики (слабые темы, рекомендации).
12. **Доверие клиенту**: сервер не валидирует XP и прогресс.
13. **Доступность не проработана**: статусы передаются цветом и иконкой без текстовых альтернатив, фокус-состояния не оформлены, нет `prefers-reduced-motion`.
14. **Нет автотестов в репозитории** — валидаторы существовали только во временной папке сессии.

## 10. Технические риски миграции

| Риск | Вероятность | Последствие | Митигация |
|---|---|---|---|
| Потеря прогресса при смене ID модулей | Высокая | Пользователь теряет XP и открытые модули | Карта `legacy→new`, миграция состояния при загрузке, версия схемы |
| Порча БД аккаунтов | Низкая | Потеря учётных записей | Бэкап сделан, миграция без изменения схемы `states` |
| Разрастание первой загрузки | Высокая | Медленный старт на мобильном | Ленивая загрузка контента по требованию (fetch JSON) |
| Некорректный перевод техтерминов | Средняя | Путаница у новичка | Единый глоссарий, код и ключевые слова не переводятся |
| Регрессия в работающих тренажёрах | Средняя | Ломается ядро продукта | Автотесты в репозиторий до рефакторинга |
| Расхождение контента и переводов | Средняя | Пустые экраны на UZ/EN | Fallback-цепочка uz→ru, en→ru + отчёт о покрытии |

## 11. Рекомендуемая стратегия миграции

**Принцип: эволюция, не переписывание.** Работающее ядро (Pyodide-раннер, SQL-раннер, автопроверка, аккаунты, синхронизация) сохраняется без изменений.

1. **Данные → JSON.** Перевести `data/*.js` в `content/**.json` конвертером; текстовые поля обернуть в `{ru, uz, en}`, код оставить общим.
2. **Ленивая загрузка.** Курс подгружается через `fetch` при открытии, а не 26 тегами `<script>`.
3. **Новая модель:** домены → карьерные пути → курсы (переиспользуемые) → модули → уроки → блоки; отдельно навыки и граф пререквизитов.
4. **Совместимость прогресса:** карта соответствия `m01→python-basics/01` и т. д.; миграция состояния при первом входе, старый формат не удаляется.
5. **Разбиение `app.js`** на модули (state, i18n, router, ui, screens) без смены парадигмы.
6. **i18n:** словарь интерфейса + мультиязычные поля контента + переключатель языка + fallback.
7. **Тесты в репозиторий** до начала рефакторинга, прогон после каждой фазы.
