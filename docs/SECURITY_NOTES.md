# SECURITY_NOTES.md — безопасность платформы

## 1. Исполнение пользовательского кода

**Пользовательский код никогда не выполняется на сервере.** Python работает через Pyodide (CPython → WebAssembly), SQL — через sql.js (SQLite → WebAssembly). Оба — в браузере ученика, в песочнице WebAssembly:

- нет доступа к файловой системе сервера;
- нет доступа к сети изнутри песочницы;
- база SQL создаётся заново для каждого запроса и уничтожается после — испортить чужие данные невозможно;
- бесконечный цикл вешает только вкладку самого ученика.

Это осознанный архитектурный выбор: серверный «Run code» без изоляции в контейнере был бы дырой, а безопасная реализация потребовала бы отдельной инфраструктуры. Браузерная песочница даёт настоящее исполнение без этого риска.

## 2. Аккаунты

- Пароли хранятся **только хешированными** (`werkzeug.security`, PBKDF2 с солью). Восстановление пароля невозможно by design.
- Токены сессий — 32 случайных байта (`secrets.token_hex`), в БД лежит только SHA-256 от токена: утечка базы не даёт войти под пользователем.
- Ограничение на перебор: 10 неудачных попыток на логин → блокировка на 10 минут.
- Валидация логина по белому списку символов (`^[a-zA-Z0-9_.\-а-яА-ЯёЁ]{3,20}$`), пароль от 6 символов.
- Все SQL-запросы к БД аккаунтов — **параметризованные** (`?`), склейки строк нет.
- Размер сохраняемого состояния ограничен 256 КБ.
- Выход очищает локальные данные — на общем устройстве следующий пользователь не увидит чужой прогресс.

## 3. Транспорт и веб-сервер

- HTTPS с сертификатом Let's Encrypt, HTTP → HTTPS редиректом.
- API доступен только через nginx-прокси; gunicorn слушает `127.0.0.1:8611` и снаружи недоступен.
- Сервис работает от `www-data`, не от root.
- `client_max_body_size 1m` — защита от больших тел запросов.

## 4. Фронтенд

- Пользовательский ввод (логин, имя на сертификате, код в редакторе) **всегда экранируется** через `esc()` перед вставкой в HTML.
- HTML без экранирования вставляется только из собственных файлов контента проекта (`content/**.json`) — они не редактируются пользователями.
- Секретов во фронтенде нет: токен живёт в localStorage и передаётся только на свой же домен.

## 5. Секреты и репозиторий

- В коде и в git нет паролей, ключей и токенов.
- Путь к БД настраивается переменной окружения `PYQUEST_DB`.
- `.gitignore` исключает `*.db`, `__pycache__/`, `backups/`.
- SSH-ключ доступа к серверу хранится только на машине владельца.

## 6. Что стоит усилить при росте проекта

Честный список того, чего сейчас нет (не выдаём за реализованное):

| Направление | Сейчас | Что нужно при публичном запуске |
|---|---|---|
| Валидация XP | на клиенте | пересчёт прогресса на сервере, если появятся рейтинги |
| Восстановление пароля | нет | e-mail + одноразовая ссылка сброса |
| Rate limiting API | только на логин | общий лимит на IP (nginx `limit_req`) |
| Бэкапы БД | ежедневный cron, 14 копий с проверкой | выгрузка копий за пределы сервера |
| Аудит входов | нет | журнал входов и активных сессий в профиле |
| CSP-заголовки | нет | `Content-Security-Policy` с разрешением на CDN Pyodide/sql.js |
| 2FA | нет | TOTP для аккаунтов с прогрессом, который жалко потерять |

## 7. Приватность

Платформа собирает минимум: логин, хеш пароля, дату регистрации и учебный прогресс. Ни почты, ни телефона, ни аналитики, ни сторонних трекеров. Единственные внешние запросы — шрифты Google Fonts и CDN Pyodide/sql.js, и те только при первом использовании тренажёра.

## Панель управления сервером в Telegram

`deploy/tgpanel/` — бот, который включает и выключает проекты на сервере.
Работает от root, потому что управляет systemd и docker. Такая власть требует
трёх ограничений, и все три заложены в код:

1. **Один адресат.** Обрабатываются только сообщения от `TG_ADMIN`. Всё
   остальное отбрасывается до разбора команды — чужой человек не получит даже
   сообщения об ошибке.
2. **Белый список.** Имена сервисов и контейнеров перечислены в самом коде.
   Из сообщения они не берутся никогда, подставить своё имя невозможно.
   Разрешены ровно три действия: `start`, `stop`, `restart`.
3. **Никакого произвольного выполнения.** Команды собираются списком
   аргументов, без `shell=True`. Удаления нет вообще — ни контейнеров, ни
   образов, ни файлов.

Токен лежит в `/opt/tgpanel/config.env` с правами `600` и владельцем root.
В репозитории его нет и быть не должно: бот читает токен из окружения.

**Если токен утёк** — перевыпустить в @BotFather (`/revoke`), заменить строку
в `config.env` и перезапустить: `systemctl restart tgpanel`. Старый токен
перестаёт работать сразу.

## Что проверяется перед публикацией

Репозиторий периодически просматривается на предмет попавших туда данных:
ключей, токенов, паролей, файлов баз. Один раз такое нашлось — токен сессии
демонстрационного аккаунта в `tools/.shots/token.txt`, попавший туда вместе со
скриншотами. Файл убран из отслеживания, каталог добавлен в `.gitignore`, а
сама сессия отозвана на сервере, чтобы старый токен ничего не открывал.

Адрес сервера в документации заменён переменной: команды остаются рабочими,
а конкретный IP в публичный репозиторий не попадает.
