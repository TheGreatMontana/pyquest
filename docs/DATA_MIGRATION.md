# DATA_MIGRATION.md — миграция данных

Мигрировали две независимые вещи: **учебный контент** (файлы проекта) и **прогресс пользователей** (их данные). Правило было одно: ничего не терять.

---

## 1. Миграция контента: `data/*.js` → `content/courses/*.json`

**Скрипт:** `tools/migrate-content.js` (идемпотентный, читает старые файлы только на чтение).

**Что сделал:**
1. Загрузил старые `data/*.js` в песочнице Node (они писали в `window.COURSE_DATA`).
2. Разложил 20 модулей по 6 переиспользуемым курсам.
3. Обернул текстовые поля в мультиязычные `{ ru: … }`; код оставил как есть.
4. Преобразовал карточки теории в уроки с типизированными блоками.
5. Записал `legacyId` в каждый модуль — это якорь для миграции прогресса.

**Разбиение:**

| Было | Стало | Модулей |
|---|---|---|
| m01–m05 | `python-basics` | 5 |
| m06–m08 | `python-intermediate` | 3 |
| m09–m10 + final | `python-advanced` (+ финальный экзамен) | 2 |
| s01–s03 | `sql-basics` | 3 |
| s04–s06 | `sql-advanced` | 3 |
| a01–a04 | `algorithms` | 4 |

**Верификация (встроена в скрипт, падает при расхождении):**

```
             уроки  вопросы  задачи  экзамены  вопр.экз  зад.экз
Было (data)     99      129      60        21       121       22
Стало (JSON)    99      129      60        21       121       22
✔ без потерь
```

Старые `data/*.js` **не удалены** — остаются в репозитории и в бэкапе как первоисточник.

## 2. Миграция прогресса пользователей (критичная часть)

### Проблема
Прогресс был привязан к старым ключам модулей: `mods.m01`, `mods.s03`… После реорганизации эти ключи перестали существовать. Наивная выкатка обнулила бы прогресс всех пользователей.

### Решение
1. **Карта соответствия** в каталоге (`catalog.legacyMap`), 21 запись:
   ```json
   { "m01": "python-basics/pb-01", …, "final": "python-advanced/final" }
   ```
2. **Функция миграции** `migrate()` в `js/core/state.js` выполняется при каждой загрузке состояния:
   - переносит `mods[legacyId]` → `modules["courseId/moduleId"]` со всеми полями (`theory`, `quizBest`, `tasks`, `examBest`, `examPerfect`);
   - переносит `finalBest` → `finals["python-advanced"]`;
   - **сохраняет исходный `mods` в поле `legacyMods`** — страховка на случай, если карта окажется неполной;
   - проставляет `schemaVersion: 2`, чтобы не мигрировать повторно;
   - идемпотентна: повторный вызов ничего не портит.
3. **Ничего не удаляется:** ключ localStorage остался прежним (`pyquest_v1`), схема таблицы `states` на сервере не менялась — миграция полностью на клиенте.
4. **Выбор источника при входе:** сравниваются локальное и серверное состояния, побеждает более полное (`stateScore` = XP × 10 + число модулей). Так прогресс не теряется ни при офлайне, ни при входе с нового устройства.

### Что сохраняется
XP · стрик · дата старта · имя · достижения · чеклист роадмапа · по каждому модулю: пройденная теория, лучший результат квиза, решённые задачи, лучший результат экзамена, флаг идеальной сдачи.

### Проверка (`tools/check-ui.mjs`, на реальном состоянии пользователя)

## 4. Откат

Если что-то пойдёт не так:

```bash
# 1. Вернуть код
git checkout main && scp -r index.html css js data root@SERVER:/var/www/course/

# 2. Вернуть БД аккаунтов (при необходимости)
ssh root@SERVER "systemctl stop pyquest-api && \
  cp /opt/pyquest-api/backups/pyquest-20260803-133215.db /opt/pyquest-api/pyquest.db && \
  systemctl start pyquest-api"
```

Прогресс пользователей при откате не пострадает: состояние хранится в старом формате-совместимом виде, а `legacyMods` содержит исходные данные.
