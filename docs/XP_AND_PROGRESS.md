# XP_AND_PROGRESS.md — опыт, прогресс и защита от накрутки

## 1. Награды (настраиваются в `catalog.json` → `xpRewards`)

| Событие | XP | Условие начисления |
|---|---|---|
| Урок теории пройден | 20 | один раз за модуль |
| Интерактивный блок решён | 15 | один раз за блок |
| Правильный ответ в квизе | 10 | только за улучшение прошлого результата |
| Задача решена | 40 | один раз за задачу |
| Экзамен сдан (≥70%) | 120 | один раз |
| Экзамен на 100% | +60 | один раз |
| Финальный экзамен курса | 300 | один раз |
| Курс завершён полностью | 100 | один раз |

Значения не зашиты в код — меняются в каталоге.

## 2. Ранги

8 ступеней: Новичок (0) → Ученик (200) → Кодер (500) → Практик (900) → Питонист (1400) → Мастер кода (2100) → Сенсей (3000) → **Инженер данных (4200)**. Названия переведены на три языка.

## 3. Защита от накрутки

Единственная точка начисления — `addXp()` в `js/core/gamification.js`. Все награды идут через функции `award*`, каждая проверяет, не выдавалась ли награда раньше:

- **теория** — флаг `theory`;
- **задача** — `tasks[taskId]`;
- **интерактивный блок** — `blocks["lessonId:index"]`;
- **квиз** — платит только за разницу с прошлым лучшим результатом (`quizBest`);
- **экзамен** — платит один раз за прохождение и один раз за 100%.

Обновление страницы, повторное открытие урока или пересдача уже сданного экзамена **не дают XP**. Это подтверждено тестами (`tools/check-ui.mjs`, блок «XP: …»).

**Известное ограничение:** начисление происходит на клиенте, сервер принимает состояние как есть. Для дружеского круга это приемлемо: обманывать имеет смысл только самого себя. Если платформа станет публичной с рейтингами — валидацию нужно переносить на сервер (см. `docs/SECURITY_NOTES.md`, раздел «Что стоит усилить»).

## 5. Где хранится

| Слой | Что |
|---|---|
| `localStorage['pyquest_v1']` | рабочая копия состояния (мгновенная запись) |
| `localStorage['pyquest_auth']` | токен сессии |
| `localStorage['pyquest_lang']` | выбранный язык |
| `localStorage['pyquest_code_…']` | черновики кода в задачах |
| Сервер, таблица `states` | тот же JSON, привязан к пользователю |

## 6. Синхронизация

- отложенная запись через 1.5 с после изменения (не спамим сервер при каждом клике);
- принудительная отправка при сворачивании вкладки (`visibilitychange` + `keepalive`);
- повтор каждые 30 с, если остались несохранённые изменения;
- при входе выбирается более полное из двух состояний (локальное / серверное) — прогресс не теряется при офлайне и подхватывается на новом устройстве;
- при истёкшем токене — мягкий выход с сообщением, локальные данные сохраняются.

## 7. Стрик

Увеличивается на 1, если последняя активность была вчера; сбрасывается в 1, если пропущен день. Обновляется при любом начислении XP, то есть за реальные учебные действия, а не за открытие страницы.

## 8. Достижения

15 достижений, включая **Полиглот** (позанимался на двух языках) и **Data Engineer** (пройден весь путь). Проверяются после каждого начисления XP функцией `checkAchievements()`; выданное достижение не выдаётся повторно.
