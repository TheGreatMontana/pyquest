# PLATFORM_ARCHITECTURE.md — архитектура платформы PyQuest

**Версия:** 2.0 (platform expansion)
**Принцип:** эволюция работающего ядра, а не переписывание с нуля.

---

## 1. Обзор

PyQuest превращается из одного курса Data Engineering в платформу, где домены (IT-направления) собираются из **переиспользуемых курсов**, связанных **графом навыков и пререквизитов**, с поддержкой **трёх языков** (ru / uz / en).

```
Домен (Data Engineering, Backend, Cybersecurity, …)
 └── Карьерный путь (стадии обучения)
      └── Курс  ←── переиспользуется несколькими доменами
           └── Модуль
                └── Урок (набор блоков)
                     └── Блок: теория | пример | задача | вопрос | найди баг | …
```

Ключевое отличие от версии 1: **курс не принадлежит домену**. `python-basics` — один курс, на который ссылаются и Data Engineering, и Backend, и AI. Прогресс по нему общий: прошёл в одном пути — засчитан в остальных.

## 2. Слои приложения

| Слой | Файлы | Ответственность |
|---|---|---|
| Данные | `content/**.json` | Каталог, курсы, уроки, переводы. Только данные, без кода |
| Загрузка | `js/core/content.js` | Ленивая загрузка курсов через `fetch`, кэш в памяти |
| Язык | `js/core/i18n.js` | Текущий язык, словарь UI, `t()`, `tr()` с fallback |
| Состояние | `js/core/state.js` | Прогресс, XP, миграция схемы, синхронизация с API |
| Граф | `js/core/graph.js` | Пререквизиты, статусы узлов, рекомендация следующего шага |
| Геймификация | `js/core/gamification.js` | XP, ранги, достижения, стрик, защита от повторов |
| Тренажёры | `js/runner.js`, `js/sqlrunner.js` | **Без изменений** — Pyodide и sql.js |
| Роутер | `js/core/router.js` | Хеш-маршруты, разбор параметров |
| Экраны | `js/screens/*.js` | Дашборд, каталог, домен, курс, урок, экзамен, роадмап, профиль |
| UI-примитивы | `js/ui.js` | Иконки, тосты, escape, подсветка кода, блоки |
| Бэкенд | `server/app.py` | Аккаунты, синхронизация прогресса, язык пользователя |

Никакого фреймворка и сборки: ES-модули (`<script type="module">`) поддерживаются всеми целевыми браузерами. Это сохраняет главное преимущество проекта — мгновенный деплой обычным `scp`.

## 3. Сущности данных

### 3.1 Домен (`content/catalog.json` → `domains[]`)
```jsonc
{
  "id": "data-engineering",
  "title": { "ru": "Data Engineering", "uz": "…", "en": "…" },
  "tagline": { "ru": "…", "uz": "…", "en": "…" },
  "glyph": "db",                 // иконка из SVG-спрайта
  "color": "#f59e0b",
  "status": "full",              // full | starter | planned — честный статус наполнения
  "careerPath": "de-path"        // ссылка на карьерный путь
}
```

### 3.2 Карьерный путь (`careerPaths[]`)
Стадии обучения; каждая стадия ссылается на курсы **по id**, а не содержит их.
```jsonc
{
  "id": "de-path",
  "stages": [
    { "id": "st-foundations", "title": {…}, "courses": ["python-basics"] },
    { "id": "st-sql",         "title": {…}, "courses": ["sql-basics", "sql-advanced"] }
  ]
}
```

### 3.3 Навык (`skills[]`)
Атомарная единица знания. Курсы дают навыки, курсы требуют навыки — так строится граф.
```jsonc
{ "id": "python-oop", "title": {…}, "category": "language" }
```

### 3.4 Курс (`courses[]` в каталоге — метаданные; `content/courses/<id>.json` — содержимое)
```jsonc
{
  "id": "python-basics",
  "title": {…}, "description": {…},
  "level": "beginner",              // beginner | intermediate | advanced
  "requires": [],                   // id навыков, нужных на входе
  "grants": ["python-syntax", "python-collections"],
  "estimatedHours": 20,
  "status": "full",
  "usedBy": ["data-engineering", "backend", "ai"],   // где переиспользуется
  "legacyIds": ["m01","m02","m03","m04","m05"]       // для миграции прогресса
}
```

### 3.5 Модуль и урок (`content/courses/<id>.json`)
```jsonc
{
  "id": "python-basics",
  "modules": [{
    "id": "pb-01",
    "legacyId": "m01",                 // ← критично для сохранения прогресса
    "title": {…}, "tagline": {…},
    "lessons": [ { "id": "pb-01-l1", "type": "theory", "blocks": [ … ] } ],
    "quiz":  [ … ],
    "tasks": [ … ],
    "exam":  { "time": 420, "questions": [ … ], "task": { … } }
  }]
}
```

### 3.6 Блоки урока
Единый формат `{ "type": "...", ...поля }`. Реализованы:

| type | Назначение |
|---|---|
| `text` | Абзац/список (HTML в мультиязычном поле) |
| `code` | Пример кода без запуска |
| `run` | Python-пример с кнопкой «Запустить» |
| `sqlrun` | SQL-пример с кнопкой «Выполнить» |
| `note` | Врезка: важно / подсказка / ловушка |
| `predict` | **Предскажи вывод** — варианты, затем реальный запуск кода |
| `findbug` | **Найди баг** — код с ошибкой, варианты строк |
| `match` | **Сопоставь** пары (понятие ↔ определение) |
| `order` | **Расставь по порядку** шаги алгоритма |
| `checkpoint` | Проверка знаний внутри урока |
| `summary` | Итоги урока списком |

Код внутри блоков **не переводится** — он одинаков на всех языках. Переводятся только текстовые поля.

## 4. Модель интернационализации

### 4.1 Мультиязычное поле
```jsonc
"title": { "ru": "Списки", "uz": "Ro'yxatlar", "en": "Lists" }
```
Разрешение: `tr(field)` → текущий язык → `ru` → `en` → первое непустое.
Так частично переведённый курс никогда не показывает пустой экран.

### 4.2 Словарь интерфейса
`content/i18n/ui.<lang>.json` — плоские ключи:
```jsonc
{ "nav.map": "Карта", "lesson.check": "Проверить", "exam.start": "Начать экзамен" }
```
Отсутствующий ключ → русский → сам ключ (видно при разработке, не ломает UI).

### 4.3 Выбор языка
Приоритет: сохранённый выбор → язык аккаунта (сервер) → `navigator.language` → `ru`.
Переключатель в шапке, выбор сохраняется в `localStorage` и в профиле пользователя.

### 4.4 Что не переводится
Код, имена функций, SQL-ключевые слова, идентификаторы, названия технологий (Python, Airflow, JOIN).

## 5. Граф пререквизитов

Узел = курс. Ребро = «навык, который курс требует, выдаётся другим курсом».

Статусы узла вычисляются, а не хранятся:

| Статус | Условие |
|---|---|
| `completed` | Все модули курса завершены |
| `in-progress` | Есть прогресс, но не завершён |
| `available` | Все требуемые навыки получены |
| `locked` | Не хватает навыков (показывается, каких именно) |

Функция `nextRecommended()` возвращает первый доступный незавершённый курс текущего пути — это питает кнопку «Продолжить» на дашборде.

**Важно:** заблокированный курс можно открыть и посмотреть; блокируется не чтение, а зачёт прогресса без основы. Пререквизиты — рекомендация с явным предупреждением, а не стена (кроме экзаменов внутри курса, где последовательность обязательна).

## 6. Режимы обучения

| Режим | Маршрут | Суть |
|---|---|---|
| Карьера | `#/domain/<id>` | Полный путь по стадиям до профессии |
| Навык | `#/course/<id>` | Один курс отдельно, без карьеры |
| Оценка уровня | `#/assess/<skill>` | 10 вопросов → уровень → рекомендация, с какого модуля начать |
| Практика | `#/practice` | Задачи из всех пройденных курсов, вперемешку |
| Проекты | `#/projects` | Крупные практические работы с чеклистом |

Оценка уровня **никогда не скрывает** базовые модули — только помечает «можно пропустить» и предлагает точку входа.

## 7. Совместимость прогресса (критично)

Состояние получает `schemaVersion`. Миграция v1 → v2 выполняется на клиенте при загрузке и на сервере не требует изменения схемы (данные по-прежнему один JSON).

```
v1: mods.m01 = { theory, quizBest, tasks, examBest, examPerfect }
v2: modules["python-basics/pb-01"] = { …те же поля… }
```
Карта `legacyId → новый ключ` хранится в каталоге (`legacyIds` курса и `legacyId` модуля). Старый объект `mods` **сохраняется** в состоянии как `legacyMods` — если миграция окажется неполной, данные не потеряны и восстановимы.

Проверка после миграции: суммарный XP не уменьшился, число завершённых модулей совпадает, открытые модули остались открытыми.

## 8. Производительность

- Первая загрузка: `index.html` + CSS + ядро JS + `catalog.json` (~60 КБ вместо 346 КБ).
- Курс подгружается при открытии (`content/courses/<id>.json`), кэшируется в памяти и в `sessionStorage`.
- Pyodide (~10 МБ) и sql.js (~1 МБ) — только при первом запуске кода, как и раньше.
- Языковой словарь — один маленький JSON на язык.

---

## 9. Безопасность

- Исполнение кода — **только в браузере пользователя** (WebAssembly-песочница Pyodide/sql.js). На сервере пользовательский код не исполняется никогда.
- Сервер: параметризованные SQL-запросы, хеширование паролей, токены-сессии, лимит размера состояния, троттлинг входа.
- Контент вставляется как HTML только из **собственных** файлов проекта; пользовательский ввод всегда экранируется.
- Секреты — через переменные окружения, в репозиторий не попадают.

## 10. Наставник (`js/core/mentor.js`)

Реализован в v2.1. Два уровня, второй опционален:

**1. Локальный наставник — работает всегда, без интернета и без AI.**

- `hintLevels(task)` — прогрессивные подсказки: направление мысли → подсказка автора задачи → скелет решения (стартовый код) → отсылка к теории модуля. **Готовое решение не выдаётся ни на каком уровне** — задача научить, а не закрыть упражнение.
- `explainError(message, kind)` — объясняет ошибку по-человечески: 15 шаблонов Python и 6 SQLite, сверенных с реальными сообщениями CPython 3.11+ и sql.js. Возвращает `{ text, matched }`; при `matched: false` даётся общий совет, как читать traceback, **без выдуманной диагностики**.

**2. AI-провайдер — опционально.**

`setProvider(impl)` принимает реализацию с методами `explain / hint / review`. Провайдер намеренно абстрактный: ключ никогда не попадает во фронтенд, запрос уходит на собственный бэкенд, который и общается с моделью.

Если провайдер не подключён (текущее состояние), `explain()` и `review()` возвращают `{ available: false }` и честный текст «AI-наставник не подключён». Никаких сгенерированных «как будто от ИИ» ответов — это покрыто отдельным тестом (`tools/check-mentor.mjs`).

## 11. Как расширять платформу

**Новый домен:** добавить объект в `domains[]` и карьерный путь в `careerPaths[]` каталога.
**Новый курс:** метаданные в `courses[]`, содержимое в `content/courses/<id>.json`, сослаться из стадии пути.
**Новый урок:** объект в `modules[].lessons[]` с массивом блоков.
**Новый пререквизит:** добавить навык в `requires` курса и в `grants` курса-источника.
**Новый язык:** `content/i18n/ui.<lang>.json` + поля `<lang>` в контенте; отсутствующее подхватится fallback-цепочкой.

Ни одно из этих действий не требует правки кода приложения.
